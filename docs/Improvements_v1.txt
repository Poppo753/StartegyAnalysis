📊 ARCHITETTURA GENERALE
La repo è un progetto di trading crypto con due componenti principali:
1. TypeScript Pipeline (src/) — Scarica dati aggTrades da Binance e li converte in OHLC 1s
2. Python Backtester (python-backtester/) — Simula strategie "Momentum + Drop" sui dati OHLC generati
🔴 PROBLEMI CRITICI TROVATI
1. TYPEORM/TypeScript — Bug nel Retry Logic (binanceClient.ts)
// PROBLEMA: Il contatore retry viene incrementato MA il delay è calcolato
// con `retries > MAX_RETRIES` invece di `retries >= MAX_RETRIES`
// E il delay esponenziale usa `retries - 1` ma parte da 1 dopo il primo errore
Problema: Se MAX_RETRIES = 5, il loop while(true) può fare fino a 6 tentativi prima di lanciare l'errore. Il calcolo del delay RETRY_BASE_DELAY_MS * Math.pow(2, retries - 1) è errato nel primo retry (dovrebbe essere retries non retries - 1).
2. TypeScript — Race Condition nel Merge File (downloadAggTrades.ts)
// PROBLEMA: mergeDayFiles() usa fs.readFileSync e fs.appendFileSync in modo sincrono
// ma le chiamate a downloadAggTrades() sono parallele. Più giorni possono
// tentare di scrivere sullo stesso file contemporaneamente.
Problema: Il merge avviene DOPO runWithConcurrency, ma ogni worker scrive il proprio file giornaliero. Se due giorni finiscono con lo stesso nome di file, ci saranno race condition.
3. Python — Bug signal-only in _calculate_pnl (simulator.py)
# PROBLEMA: In signal-only, fees = 0.0 è commentato come "Nessuna fee in signal-only"
# ma il calcolo dei fees è stato già fatto PRIMA di questa condizione:
# fees = params.position_size * params.fee_rate * 2.0
# Poi viene sovrascritto a 0.0, ma la variabile fees è già calcolata inutilmente.
Meno critico: è solo inefficienza, non un bug funzionale.
4. Python — Bug di Concurrency nel Fast Engine (fast_runner.py)
# PROBLEMA: Il warmup numba usa i primi 100 dati ma NON verifica che
# i dati abbiano almeno 100 righe prima di fare il warmup.
Rischio: Se il dataset ha meno di 100 candele, il warmup crasha.
5. Python — Bug nello Split Train/Validation (data_splitter.py)
# PROBLEMA: Lo split è basato su INDICE, non su DATA.
# Se i dati non sono perfettamente uniformi, il 70% potrebbe non corrispondere
# esattamente al 70% del periodo temporale.
Esempio: Se ci sono 1000 righe ma 200 sono del 2026-01-01 e 800 del 2026-01-02, lo split a indice 700 metterebbe tutto il 2026-01-01 in TRAIN e metà del 2026-01-02 in VALIDATION.
6. TypeScript — Perdita di Dati nel Filtro (downloadAggTrades.ts)
// PROBLEMA: Il filtro `t.T >= startMs && t.T < endMs && t.T <= windowEndMs`
// è ridondante (t.T <= windowEndMs è già implicito da startTime/endTime).
// MA il problema è che `startTime` è `lastTradeId === undefined ? currentStartMs : undefined`
// Quando lastTradeId è definito, startTime è undefined e il filtro non filtra per start.
Rischio: Potenziale perdita o duplicazione di dati ai boundary dei window.
7. Python — Import Path Issues (data_loader.py, simulator.py, ecc.)
# PROBLEMA: Usano `from src.config import Config` ma dipende dal contesto di esecuzione.
# Con `python main.py` funziona grazie a sys.path.insert(0, os.path.dirname(...))
# Ma se importato come modulo, fallisce.
8. TypeScript — bulkAvailability.ts Parsing XML Fragile
// PROBLEMA: Usa `xml.includes(zipFile)` per verificare disponibilità.
// Se il nome del file appare come substring di un altro nome, falso positivo.
Esempio: Se BTCUSDT-aggTrades-2024-01-01.zip è disponibile, xml.includes("BTCUSDT-aggTrades-2024-01-01.zip") potrebbe matchare anche BTCUSDT-aggTrades-2024-01-01.zip.backup.

🟢 ASPETTI POSITIVI
1. Architettura modulare ben strutturata — TypeScript e Python hanno chiara separazione dei responsabilità
2. Streaming efficiente — aggregateStreaming.ts e extractRange.ts processano file line-by-line senza caricare tutto in memoria
3. Multi-engine approach — Python ha 3 livelli di performance (standard/fast/gpu)
4. Anti-overfitting — Il sistema GPU ha train/validation split temporale
5. Bulk download fallback — Il sistema scarica da data.binance.vision quando disponibile, altrimenti usa REST API
6. Rate limiting robusto — GlobalRateLimiter + request delay + exponential backoff
7. Formato dati coerente — JSONL per raw, CSV per OHLC, struttura standardizzata

// bulkDownloader.ts — Sostituire child_process con jszip
import { ZipFile } from 'jszip';

async function unzipFile(zipPath: string, targetDir: string): Promise<void> {
  const zip = await ZipFile.loadAsync(await fs.promises.readFile(zipPath));
  for (const [name, file] of Object.entries(zip.files)) {
    const content = await file.async('nodebuffer');
    await fs.promises.writeFile(path.join(targetDir, name), content);
  }
}
